执行链路

Center Runtime v2 的核心职责是把意图变成可审计、可等待、可取消、可恢复、可观察的执行过程。

1. IntentAgent、Console 或 CLI 提交用户意图，生产主路径是流式 Agent 调用。
2. DiscoveryCapability Registry 通过 meta tools 搜索、描述和选择具体 source。
3. GuardExecutionGuard 检查硬事实：缺槽位、读写路径、runtime、空间、preflight。
4. PolicyPolicyEngine 根据 execution mode、risk、effect 判断 allow、ask 或 deny。
5. AdmissionAdmission 决定 inline、sync wait、waitable operation 或 workflow operation。
6. RuntimeCenterExecutionRuntime 创建 Invocation、Job、Operation 或 TransferSession。

Capability Registry

维护 definition/source。Agent 默认不直接看到所有 Node 能力，而是通过 capability.search、capability.describe、capability.invoke 进入。

Operation Runtime

长任务承载在 Operation 上，Transfer、Job、ApprovalWait、Maintenance 都通过 handler 投影状态和进度。

AgentRun Checkpoint

Provider 输出、tool observation、waiting_operation、waiting_approval、final/failure 都记录为结构化步骤。

Timeline / Artifact

Timeline 是审计和追踪主干。Artifact 用于截图、日志、小中型文件和媒体展示，不承担默认大文件跨 Node 数据面。

YQP 生命周期

Node 与 Center 的稳定通道是出站 HTTPS/YQP。Node 轮询领取 Job，上报事件和终态；Node 不是业务事务发起者。

Node 接入
node.hello、heartbeat、capability snapshot registration、runtime facts。Center 写 registry 和 liveness 事实。
Job 下发
job.poll 返回可领取 Job；Node 进入 accepted/running，执行本地 capability 或插件适配。
过程事实
job.event 写入 Timeline，并投影到 Job progress read model。事件只表示过程事实，不直接改变终态。
终态收敛
job.finished 进入 succeeded、failed、cancelled 或 timeout。终态不可变，状态转换必须经过 state machine。
恢复与对账
Node reconnect 后通过 reconcile 报告本地事实。Center 根据 Operation、Job、TransferSession 和 ledger 判断下一步。

大文件传输

Center 只调度，不中转文件主体。跨 NAT 默认用 yq-croc relay-capable 数据面；公共 relay 不承诺单次必达，失败后由 Center 创建下一次 attempt 或 resume。

1. Preflight

transfer.preflight 调用两端 *.transfer.local.stat 与 *.transfer.croc.status，确认源可读、目标可写、runtime 可用、relay 可达。

2. TransferSession

Center 生成 transfer_id、code_hash、route_policy、attempt。先启动 sender，等待结构化 sender_ready。

3. Receiver Job

sender ready 后启动 receiver。两端 Node 只执行当前 Center Job，不自行换 relay、换 code、重试或 resume。

4. Data Plane

sender/receiver 都出站连接同一个 relay。relay 转发 croc 加密数据，不读取文件内容。

5. Progress

yq-croc stdout NDJSON 事件由 Node adapter 映射为 YQP job.event，Center 聚合成 Operation 进度。

6. Resume

跨 Job resume 只能由 Center 发起。Node ledger 是事实存储，不是调度队列。

传输路径的固定边界：不通过 Center API/YQP JSON/Agent prompt 转发大文件；不让 Node 自主发起业务事务；不让旧 croc CLI fallback 污染当前方案；不把公共 relay 失败伪装成业务成功。

五个 Node 的角色假设

Node 位置与网络 注册能力 运行时要求 典型任务
winClient 家庭 Windows，NAT 后，仅出站 HTTPS/YQP 和 relay egress。 windows.file.*、windows.transfer.croc.*、artifact download。 daemon 在线；yq-croc.exe 可执行；防火墙允许出站 relay TCP。 发送游戏包、拉取 artifact、执行 Windows 本地诊断。

nas-node 家庭或办公室 NAS，存储容量大，网络可能低速或受限。 文件 stat、hash、disk_usage、artifact cache、transfer receive。 严格资源锁；写操作 serial；传输必须支持 progress/cancel。 归档、备份、跨 Node 文件落地。
mac-studio-node 未来 macOS 工作站，同样只按 YQP 接入。 按 Node capability contract 注册平台前缀能力。 manifest 声明 runtime_kind、labels、interactive、privilege。 媒体处理、构建任务、本地工具桥接。

边界与当前风险

这部分是架构上的硬边界和近期需要继续收口的点，避免实现重新变成大入口或隐式 fallback。

Center 是唯一事务调度者

TransferSession、attempt、relay 选择、code 生成、取消、resume 都由 Center 建模和审计。Node 不能自行创建业务事务。

Node 只执行当前 Job

Node 可以在当前进程内 reconnect，但不能跨 Job 自主 resume、切 relay、换 code 或通知另一端。

公共 relay 不是可靠性承诺

公共 relay 失败必须可诊断、可重试、可 resume。高稳定性需要受控 relay 或 relay pool。

长任务不让 LLM 轮询

长任务进入 Operation，AgentRun 进入 waiting_operation，Console 展示进度；恢复通过 context_refs 或 resume-run。

Artifact 不替代大文件传输

Artifact 适合截图、日志、小中型文件和展示。Node-to-Node 大文件默认走 yq-croc 数据面。

Agent 上下文需要预算

能力发现和工具结果必须有投影、分页、摘要和 result_ref，避免大输出反复进入 LLM 上下文。
