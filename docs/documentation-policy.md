# 文档维护规范

状态：当前项目规定  
更新时间：2026-07-06

本文定义 YeQu Center 文档的维护规则。所有后续文档更新、归档、迁移和自动化脚本都必须遵守本规范。

## 1. 编码规则

所有项目文档必须使用 **UTF-8** 编码保存。

适用范围：

- `*.md`
- `*.txt`
- 根目录 `README.md`
- 根目录 `AGENTS.md`
- `docs/` 下所有文档
- 未来新增的设计、协议、待办、复盘、交接文档

规则：

1. 不允许提交 GBK、ANSI、UTF-16 或混合编码文档。
2. 新增文档必须直接保存为 UTF-8。
3. 修改旧文档前，如发现乱码或编码不确定，先确认编码并转换为 UTF-8。
4. PowerShell 中读取中文文档时，应先设置：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

5. 自动化脚本写入文档时必须显式使用 UTF-8。
6. 如果文档已出现中文乱码，不允许继续在乱码段落上叠加修改；应归档旧版本并重写新版本，或先恢复为可读 UTF-8。

## 2. 文档语言

当前有效文档以中文为主。

可以保留英文的内容：

- 代码标识符；
- API 路径；
- 数据库表名；
- 类名、函数名、配置项；
- 第三方项目名；
- 协议字段；
- 原始错误码；
- 必须精确引用的英文术语。

不建议在当前有效文档中混杂大段英文说明。旧文档可以保留历史形态，但新增权威文档应优先中文化。

## 3. 文档状态

文档必须能从标题或开头判断状态。

推荐状态：

| 状态 | 含义 |
|---|---|
| `current` | 当前权威说明。 |
| `active todo` | 当前执行待办。 |
| `proposal` | 设计提案，尚未完全采用。 |
| `accepted proposal` | 已决定采用，但尚未全部实现。 |
| `baseline` | 已验收阶段性基线。 |
| `superseded` | 已被新文档取代，只保留历史意义。 |
| `archive` | 归档文档，不再指导当前开发。 |
| `postmortem` | 事故复盘或排障记录。 |

## 4. 归档规则

当一份文档需要大幅重写时，优先考虑归档旧版本，而不是在旧文档中堆叠相互冲突的新章节。

应归档的情况：

- 旧文档描述的架构边界已经被新主线取代；
- 旧文档中有大量已完成、已废弃或已证明不正确的计划；
- 旧文档出现编码损坏且难以可靠恢复；
- 新设计需要保留旧实现演进过程供追踪。

归档后，必须在索引中说明：

- 旧文档为何不再权威；
- 新权威文档是哪一份；
- 旧文档是否仍可作为背景材料阅读。

## 5. 一致性规则

更新一份架构文档时，应同步检查以下文档是否需要调整：

- `docs/documentation-index.md`
- `docs/todos/README.md`
- `docs/current-project-overview.md`
- 协议合同，例如 `YQP-Node-Protocol.md`
- 前后端事件合同，例如 `docs/agent-sse-contract.md`
- 相关专题待办，例如 transfer、provider、Tool RAG、Agent runtime 文档

不得出现同一阶段内互相矛盾的权威描述。

如果短期内必须保留旧行为，应明确写成：

```text
当前实现：...
目标形态：...
迁移期间：...
```

活跃待办还有额外要求：

1. 如果待办文档经过实现后变成“部分完成、部分未完成”，必须在文档顶部维护
   `当前实现核对` 或等价状态表。
2. 状态表必须列明：事项、当前状态、代码/测试事实、剩余动作。
3. 目标态文档不能使用“当前已具备”“当前链路为”等措辞描述尚未实现的内容；
   必须写成“目标态”“待办”或“未完成”。
4. 代码提交完成某个待办项时，应同步更新对应文档；不能让 active todo 保持
   未完成口吻误导后续执行。

## 6. 实现事实来源

当文档与代码冲突时，按以下顺序判断：

1. 当前运行代码与数据库迁移；
2. 当前测试；
3. 当前协议合同；
4. 当前权威架构文档；
5. 历史待办与归档文档。

发现冲突后，不应让实现迁就过期文档；应更新文档或明确归档旧文档。

## 7. 当前项目特别规则

YeQu Center 当前处于快速迭代期。文档应服务于架构清晰和下一阶段执行，而不是为了兼容历史描述。

因此：

- 可以明确废弃旧设计；
- 可以归档过期计划；
- 可以把旧模块标为 legacy；
- 可以提出破坏式重构；
- 但必须把“当前实现”和“目标实现”区分清楚。
